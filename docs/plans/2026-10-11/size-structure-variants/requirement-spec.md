## 0. 요구사항 원문 (인터뷰 기록)

- **원문:**
  - "결국 좋은 아키텍처면 크게 차이가 없다는거고 그렇다면, 코드베이스가 작아서 그런가 지금의 fream은?"
  - "이 부분을 먼저 해결하는게 맞다고 봐 이 궁금증을" (Spring Framework 실험보다 먼저)
- **Q/A:**
  - 설계 → **fream 변형 2×2**: 크기(원래 / 부풀림 약 5배) × 이름(업무 용어 / 난독화). 같은 과제·테스트를 재사용한다.
  - 조건 → **B + 자동 지도**. 자동 지도는 변형마다 navgraph로 다시 만들고, CLAUDE.md(C)로 전달한다. 원본에서 AC 1.01 vs AF 1.15로, 고정비가 덜한 C를 택했다.
  - 규모 → **Sonnet, 5회**:
    - 변형 3개 × 8과제 × 2조건 × 5회 = 240회
    - 기준(원본) B·AC는 기존 3회에 2회를 더해 5회로 맞춘다(+32회).
  - 미끼 → **기존 도메인 변형 복제**: 접두어 변형(Admin·Settlement·Legacy·V2 등)으로 이름 충돌을 피한다. 원래 이름으로 grep하면 미끼도 걸린다.
  - 난독화 범위 → **타입·패키지 이름 + 주석 제거**. 메서드·필드·URL·메시지 문자열은 유지한다.

## 1. 목표·대상 (필수)

- **대상:** `graph-nav-experiment`(새 브랜치 `feat/size-structure-variants`, `feat/setup-target`에서 분기)
- **만들 것:** fream-back 변형 3개를 만든다.
  - `inflated`(부풀림)
  - `obfuscated`(난독화)
  - `inflated-obfuscated`(둘 다)
- **실행:** 기존 8과제를 Sonnet × {B, AC} × 5회로 돌린다. 원본 B·AC에는 2회를 추가한다.
- **끝의 정의:** 변형별 AC÷B를 비교해 "그래프 효과가 작았던 원인이 크기(grep 잡음)인가, 이름 구조인가"를 판정하는 분석을 문서화한다.

## 2. 경계·불변식 (필수)

- **동작 보존:** 각 변형은 원본과 동작이 같아야 한다.
  - 원본 고정 테스트 294개(매핑 적용본)가 변형에서 모두 통과한다.
  - 각 과제의 정답 패치(매핑 적용본)를 적용하면 hidden·visible·회귀가 통과한다.
  - 정답 패치를 적용하지 않은 원본 상태에서는 hidden이 실패한다.
- **미끼 격리:** 미끼 코드는 진짜 흐름(컨트롤러 → 서비스 → 리포지토리)에서 호출되지 않는다. 미끼를 고쳐도 hidden은 통과하지 않는다.
- **난독화 매핑:**
  - 하나의 결정적 매핑(원래 이름 → 무의미 이름, 시드 고정)을 대상 코드·과제 공개 파일·oracle(hidden 테스트·정답 패치·relevant.txt·체크리스트 근거)에 똑같이 적용한다.
  - 매핑표는 에이전트에게 주지 않는다.
- **과제 문장:**
  - TASK.md의 업무 증상 서술(한국어)은 바꾸지 않는다.
  - 클래스·패키지 이름이 나오면 매핑을 적용한다.
- **격리·감사·판정 방식:** ADR-0001 D5·D6과 기존 러너를 그대로 쓴다. 변형별로 대상·과제·oracle·지도 경로만 바뀐다.
- **크기:** 부풀림 변형의 본 코드 Java 줄 수는 원본의 4~6배다.

## 5. 검증 방법 (필수)

- **변형마다 확인:**
  - 빌드 green, 고정 테스트 294/294
  - 과제 01~06: 원본 상태에서 hidden 실패 → 정답 패치 적용 후 hidden·visible·회귀 통과 (러너 `judge` 직접 호출)
  - 미끼만 고친 패치를 적용하면 hidden이 실패하는지 표본 1건으로 확인
- **난독화 누출 점검:** 변형 사본(에이전트가 보는 것)에서 원래 타입 이름·도메인 패키지 이름의 grep 결과가 0이다(허용 목록: 메서드·필드·문자열에 남는 것).
- **부풀림 크기:** 본 코드 Java 줄 수를 원본과 비교해 4~6배인지 확인한다.
- **grep 잡음 실측:** 과제별 대표 증상 단어로 grep한 결과 줄 수를 변형마다 기록한다(부풀림에서 늘었는지).
- **실행:** 러너 dry-run으로 변형 사본 구성을 확인한 뒤 본 실행. 유효 행 수를 대조하고 무효 행은 재실행한다.

## 8. load-bearing 가정 (1~2개)

1. **텍스트 매핑만으로 안전하게 난독화할 수 있다.** 타입 이름 → 무의미 이름을 단어 경계 치환 + 경로 이동으로 하면 빌드와 294 테스트가 green이다. QueryDSL Q타입(`QOrder` → `Q<새이름>`)과 JPQL 문자열 안의 엔티티 이름도 같은 규칙으로 처리된다. 착수 직후 obfuscated 변형으로 빌드·테스트 스모크를 한다.
2. **접두어 복제 미끼가 컴파일되고, JPA 슬라이스 테스트에서 충돌하지 않는다.** 엔티티·빈 이름 충돌이 없어야 한다. inflated 변형으로 스모크한다.
