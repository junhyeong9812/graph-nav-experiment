# ADR-0001: 탐색 그래프 실험 설계

- 상태: 채택 (2026-10-10)
- 관련:
  - `docs/plans/NEXT.md`
  - `docs/target-suspected-bugs.md`
  - compare-issue-archive ADR-0001~0006: 러너, 격리, 감사, ÷B 지표를 승계한다.

## 질문

큰 레거시 코드베이스에서 **코드·파일 탐색 그래프를 미리 주면** 헤드리스 에이전트의 탐색 비용(총 토큰)이 줄고 정답률이 오르는가.

- 그래프 종류(자동 생성 / 사람이 쓴 문서 / LLM이 만든 지도)에 따라 다른가.
- 제공 방식(파일 + "먼저 읽어라" / CLAUDE.md 자동 로드)에 따라 다른가.

## 맥락

- compare-issue-archive 결론:
  - 모델이 아는 지식은 기록해도 가치가 없다.
  - 모델이 모르는 고유 사실은 토큰을 절반 안팎 줄인다.
  - 의사결정 기록은 위반을 막는다.
  - 그 실험의 케이스는 수백 줄짜리였다. 그래서 "어디를 봐야 하는지 찾는 비용"은 재지 못했다.
- 대상은 `target/fream-back`이다.
  - 본 코드 Java 약 8만 줄, 도메인 20개, 리팩토링 전 레거시다.
  - 모델이 외웠을 가능성이 낮다(원본은 비공개 전환, 별 0).
  - 기존 동작 고정 테스트 294개가 있다.

## 결정 (사용자 인터뷰 2026-10-10)

### D1. 조건 7개

| 조건 | 그래프 | 제공 방식 |
|---|---|---|
| B | 없음 | — |
| AF | 자동 생성 | 파일 + "먼저 읽어라" |
| AC | 자동 생성 | CLAUDE.md |
| HF | 사람이 쓴 문서(`target-docs`) | 파일 + "먼저 읽어라" |
| HC | 사람이 쓴 문서 | CLAUDE.md |
| LF | LLM 지도(Opus 1회 생성) | 파일 + "먼저 읽어라" |
| LC | LLM 지도 | CLAUDE.md |

- **파일 방식(F):**
  - 사본 루트에 `NAV.md`(진입 인덱스)를 두고 `nav/`에 상세를 둔다.
  - 프롬프트는 "작업 전에 `NAV.md`를 먼저 읽고 필요한 상세만 열어라"이다(1차 교훈: 선택적 안내는 열리지 않는다).
- **CLAUDE.md 방식(C):**
  - 인덱스를 사본 루트 `CLAUDE.md`에 넣고, 상세는 `nav/` 파일로 둔다.
  - 프롬프트는 B와 같다.
  - 격리 HOME에서도 프로젝트 CLAUDE.md가 로드되는지 러너 스모크로 확인한다.
- **인덱스 크기:** 세 그래프 모두 인덱스는 약 8KB(약 2~3천 토큰) 안쪽으로 맞춘다. CLAUDE.md는 매 턴 고정비가 되므로 크기를 맞춰야 그래프 종류끼리 비교할 수 있다. 상세(`nav/`)는 크기 제한이 없다.

### D2. 그래프 종류

- **자동 생성(A):** 스크립트로 만든다. 사람이나 LLM의 해석은 넣지 않는다.
  - 인덱스: 도메인별 한 줄(패키지, 파일 수, 주요 진입점 컨트롤러, 다른 도메인 의존)
  - 상세(도메인별):
    - 엔드포인트 → 컨트롤러 → 서비스 → 리포지토리 호출 사슬
    - 클래스 의존(생성자 주입·import)
    - JPA 엔티티 연관
    - 이벤트·Kafka 발행 → 구독 연결
    - 테스트 위치
- **사람이 쓴 문서(H):** `target-docs/fream-back`(4fd438f 시점 README와 docs)을 그대로 쓴다.
  - 인덱스는 루트 README를 요약 없이 잘라 쓰고, 문서 목록을 붙인다.
  - 일부 문서는 낡았을 수 있다. 실제 레거시 문서도 그렇다.
- **LLM 지도(L):** Opus가 과제를 모르는 상태로 사본을 읽고 "다음에 올 에이전트를 위한 CLAUDE.md와 아키텍처·흐름 문서"를 1회 쓴다.
  - 모든 실행이 같은 지도를 쓴다.
  - 생성 토큰은 고정비로 따로 보고하고, 손익분기(몇 회 실행부터 이득인가)를 계산한다.

### D3. 과제 8개 (유형당 2)

| 유형 | 내용 | 판정 |

### D4. 규모·모델·예산

- 8과제 × 7조건 × 3회 × Sonnet·Haiku = **336회**
- 실행당 상한 $5. 동시 실행 ≤5, 같은 과제는 동시에 돌리지 않는다.
- LLM 지도 생성(Opus 1회)은 실행 수에 넣지 않는다.

### D5. 격리·오염 방지

- compare-issue-archive 러너를 승계한다: 격리 HOME, 실행별 TMPDIR, 작업 폴더 사본, 감사.
- WebFetch·WebSearch는 deny한다.
- 아래가 로그에 보이면 감사에서 무효로 처리한다.
  - Bash 네트워크 명령: `curl`, `wget`, `git clone`·`fetch`, `gh`

## 예측과 판정

- 가설: 그래프는 B 대비 토큰을 줄인다(÷B < 0.8). 효과는 변경 요청과 반복 패턴(영향 범위 찾기)에서 가장 크고, 버그 수정에서 가장 작다(증상에서 grep으로 추적 가능).
- CLAUDE.md 방식은 인덱스가 매 턴 고정비가 된다. 그래서 턴이 길면 손해일 수 있다.
- 사람이 쓴 문서는 낡은 부분이 있어서, 4차의 낡은 카드처럼 오히려 손해일 수 있다.
- 판정:
  - ÷B 0.8 미만이면 효과 있음.
  - 0.8~1.0이면 미미("드라마틱하지 않다"는 사용자 직관과 일치하는지 본다).
  - 1 이상이면 손해.

## 확정 (2026-10-10)

- 자동 그래프 생성 도구: **javaparser 기반 Java 도구**. 실험 저장소 `tools/`에 별도 Gradle 프로젝트로 두고, 대상 코드에는 의존성을 추가하지 않는다.
- 러너: compare-issue-archive `run_experiment.py`를 **복사해 고친다**. 원본 저장소는 건드리지 않는다.
- 이해 질문 채점: 과제마다 정답 체크리스트를 둔다. 조건을 모르는 Opus가 채점하고, 메인이 표본을 검수한다. 체크리스트 형식은 과제 작성 때 정한다.
