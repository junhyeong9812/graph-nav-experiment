# graph-nav-experiment

큰 레거시 코드베이스에서 **코드·파일 탐색 그래프를 미리 주면 헤드리스 코딩 에이전트(`claude -p`)의 탐색 비용이 줄고, 코드베이스를 더 빨리 이해하는가**를 재는 실험장이다.

[compare-issue-archive](https://github.com/junhyeong9812/compare-issue-archive)의 결론 4번(미검증 가설)을 이어받는다. 그 실험은 이슈·결정 기록의 가치를 쟀고, 이 실험은 구조 지도의 가치를 잰다.

## 최종 결론 (2026-10-12)

**에이전트의 탐색 비용과 정답률을 정한 것은 미리 만든 지도가 아니라 코드베이스 자신의 아키텍처와 이름이었다.**

- **아키텍처의 지엽성**(도메인별 규칙적 패키지 + 역할 접미어)은 도메인 안의 탐색 비용을 묶는다. 코드를 4.3배로 키워도 지도 없는 탐색 비용은 1.27배였다.
- **이름**은 도메인 경계를 넘어 맞는 부품을 찾게 한다. 타입·패키지 이름을 지우면 비용은 그대로인데, 근처 부품으로 때우는 실패가 늘었다(성공 25 → 21).
- 자동 지도는 이름이 망가진 코드에서 정답률을 되찾을 때만 쓸모가 보였다(LLM 지도의 좁은 토큰 절감 경향은 결론 1). 그것도 구조 정보가 아니라 지도에 남은 업무 단어(URL)가 다리 역할을 했다.
- **이름 대응표(2026-10-12):** 도메인 이름 19줄(539B)을 CLAUDE.md에 두면 자동 지도(6.3KB)만큼 정답률을 되찾았다. 더 자세한 대응표(10KB)는 토큰만 늘렸다.
- **틀린 이름(2026-10-12):** 타입·패키지의 업무어를 도메인끼리 맞바꿔도 토큰은 그대로였다(1.03). 정답률은 원본과 의미 없는 이름의 중간(25 · 22 · 21)이었다. 메서드·URL·문자열이 맞는 단서를 유지했기 때문으로 본다.
- 아키텍처가 없는 코드, 메서드·문자열까지 틀린 코드는 재지 않았다. 아래 세 실험이 근거다.

## 결론 1: 지도 7조건 (2026-10-11)

**규칙적인 레거시(Java 약 8만 줄)에서 미리 만든 탐색 그래프는 에이전트 토큰을 의미 있게 줄이지 못했다.**

- **규모:** 336회(7조건 × 8과제 × 3회 × Sonnet·Haiku)를 실행했다.
- **토큰:** 지도 없는 조건 대비 총 토큰은 Sonnet 0.87~1.15, Haiku 1.10~1.22다. 사전 기준(< 0.8)을 만족한 조건이 없다.
- **성공률·질문 점수:** 차이가 없다.
- **원인:** 지도가 없어도 원인 파일에 3턴이면 닿는다. grep으로 충분히 찾히는 구조라 지도는 고정비만 더했다.
- **좁은 예외:** Sonnet + Opus가 만든 LLM 지도에서만 반복 패턴·이해 질문 과제의 절감 경향이 보였다(0.62~0.82). 구간은 1을 포함하고, 지도 생성비 회수에 약 340회가 필요하다.

상세: `docs/analysis.md`, 설계: `docs/adr/0001-graph-nav-experiment-design.md`

## 결론 2: 크기와 이름을 따로 바꿔 보면 (2026-10-12)

fream을 4.3배로 부풀린 변형과 타입·패키지 이름을 지운 변형을 만들어 B·AC(자동 지도)를 Sonnet 5회씩 다시 돌렸다(272회).

- **크기:** 4.3배에서도 B 비용은 1.27배, 지도 효과는 0.96(구간이 1 포함)이다. "코드가 작아서"는 주된 원인이 아니다.
- **이름:** 이름을 지워도 비용은 늘지 않았다. 성공은 25 → 21(크기까지 키우면 19)로 떨어졌다. 지도를 주면 25·23으로 회복했다. 지도에 남은 URL 문자열이 "무엇이 무엇인지"를 알려 줬다.

상세: `docs/analysis-size-structure.md`

## 결론 3: 이름 대응표와 틀린 이름 (2026-10-12)

- 대응표 3종(539B·2.3KB·10.3KB) vs 자동 지도, 난독화 변형에서 120회. 틀린 이름 변형 B·AC 80회.
- 가장 작은 대응표가 지도와 같은 정답률(24 vs 25, 과제 05 5/5)을 냈다. 토큰은 어떤 조건도 B보다 줄지 않았다.
- 틀린 이름은 토큰을 늘리지 않았고 정답률을 25 → 22로 낮췄다(의미 없는 이름은 21).

상세: `docs/analysis-naming.md`

## 구조

```
target/fream-back/   실험 대상 — fream-back 4fd438f(리팩토링 전) 스냅샷 + 빌드 수선 + 기존 동작 고정 테스트
target/SOURCE.md     출처·제외 목록·수선 내역·알려진 한계
target/patches/      빌드 수선 패치
target-docs/         원본에 있던 사람이 쓴 문서(조건 재료, 에이전트 기본 사본에는 없음)
scripts/check-target.sh   빌드 + 테스트 확인
docs/                작업 기록·의심 지점 목록·분석(에이전트에게 주지 않음)
tools/navgraph/      자동 지도 생성기(javaparser)
graphs/              조건별 지도: auto(기계 추출) · human(원본 문서) · llm(Opus 1회 생성)
cases/ · oracle/     과제 8개(공개 파일) · 판정 자료(숨김 테스트·정답 패치·체크리스트)
scripts/             러너 run_experiment.py · 채점 grade_answers.py · 집계 analyze.py
results-*/           실행 기록(runs.jsonl·grades.jsonl·raw 로그·답안)
```
