# 질문: 구매자 배송은 운송장 등록부터 배송 완료까지 어떻게 처리되나

결제가 끝난 주문에는 구매자에게 가는 배송 정보가 하나 붙는다. 이후 운영 측이 이 배송에 택배사와 운송장 번호를 등록하고, 시스템이 택배사 조회 결과를 보고 배송 완료를 처리한다.

이 흐름이 서버에서 어떻게 처리되는지 코드를 읽고 답하라. 코드는 고치지 않는다.

1. **운송장 등록 요청**
   - 어느 API로 들어오나?
   - 어떤 엔티티의 상태가 어떤 순서로 바뀌도록 짜여 있나? 누구에게 어떤 알림이 가도록 짜여 있나?
   - 결제·배송 처리를 마친 실배송 일반 구매 입찰 주문(즉시 구매가 아닌 것)에 대해 실제로 끝까지 성공하나? 실패한다면 어디서 왜 실패하고, 무엇이 저장되며, 응답은 무엇인가?
2. **배송 완료 감지**
   - 배송 완료는 누가, 언제, 어떻게 감지하나?
   - 주기 실행이 있다면 주기는 얼마인가? 어떤 배송을 대상으로 조회하나? 실제로 실행되는 처리 코드는 무엇인가? 비슷한 코드가 여러 곳에 있으면 실제로 실행되는 쪽을 골라라.
   - 택배사 상태 문자열은 내부 상태로 어떻게 바뀌나?
3. **배송 완료 판정 이후**
   - 어떤 엔티티의 상태가 어떤 순서로 바뀌나?
   - 누가 어떤 알림을 몇 건 받나?
   - 주문 입찰·판매 입찰의 상태는 어떻게 되나?
4. **주문 종류별 차이:** 3의 처리가 아래 두 주문에서 각각 끝까지 진행되나? 결과는 어떻게 다른가?
   - (a) 결제·배송 처리를 마친 실배송 일반 구매 입찰 주문
   - (b) 즉시 구매로 만들어진 주문
5. **실패 처리:** 주기 처리 중 한 건이 실패하면 그 건과 나머지 건은 어떻게 되나?

주석이나 메서드 이름이 말하는 의도와 코드의 실제 동작이 다르면, 실제 동작을 답하라.

## 답 형식

저장소 루트에 `ANSWER.md`를 쓴다.

- 위 질문 번호별로 단계별 답을 쓴다.
- 각 단계에 근거를 `파일경로:줄`(예: `src/main/java/.../Foo.java:120`) 형식으로 붙인다. 근거 없는 주장은 점수를 받지 못한다.
